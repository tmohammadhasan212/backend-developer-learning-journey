# Learning Log

My weekly study journal for the [Backend Developer Roadmap](./backend_roadmap.md) — 0 to hired in 2 years (~30 hrs/week, 6 days/week, 1 mandatory rest day).

This repo is the **Week 0 deliverable**: a log I fill in every week (topic, hours, what I built, blockers) and commit to GitHub.

## How to use

1. Copy the blank template below into a new entry under **Weekly Log**.
2. Fill it in at the end of each week (or as you go).
3. Commit and push: `git add README.md && git commit -m "Week N log" && git push`.

Rules from the roadmap: 30 hrs/week is the target (any amount > 0 counts — log the real number), 1 rest day per week is mandatory, and buffer weeks are for catch-up or project polish.

## Example entry

```markdown
## Week 1 — Phase 0: Orientation & Environment Setup — Python install, Git, GitHub

**Hours studied:** 27 / 30
**Topic covered:** Environment setup — Python 3, venv, Git basics, first GitHub repo, VS Code + Copilot.
**What I built:** This `learning-log` repo with ≥5 commits; a hello-world CLI script that takes input and prints formatted output.
**Blockers:** `python3` pointed to an old version — fixed by updating PATH after installing via python.org installer. Git identity wasn't configured; fixed with `git config --global user.name/email`.
**What clicked this week:** What a REPL is; why virtual environments exist.
**What I'm still fuzzy on:** The difference between `git merge` and `git rebase` (Phase 2 topic, but it came up).
**AI tool usage — what worked, what I had to override/correct:** Asked Copilot to explain venvs, then verified against the official Python docs — the AI answer omitted that venvs are per-project.
**Next week's focus:** Phase 1 — Python fundamentals: syntax, variables, control flow.
**Confidence check (1–5) on this week's main topic:** 4
```
